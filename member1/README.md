# Prompt Analysis & Evaluation (Member 1 Module)

This directory contains the complete implementation for **Member 1's** module of the **PromptOpt** IEEE conference project:
**PromptOpt: AI-Driven Prompt Effectiveness Prediction using Bayesian Search and Gradient-Based Prompt Refinement**

---

## 1. Module Responsibility & Purpose

Member 1 is responsible for the **Prompt Analysis & Evaluation** phase. This module operates at the entry and exit points of the optimization pipeline, resolving two critical questions:
1. **Prompt Analysis**: *"How good is the input prompt, and what are its weaknesses?"*
2. **Response Evaluation**: *"Is the optimized response generated by the refined prompt better than the original response?"*

This module remains completely standalone, decoupled from databases, UIs, APIs, or specific optimization algorithms, allowing it to be imported and used directly by Member 2 (Prompt Optimizer) and Member 3 (Integration & UI/Backend).

## 5. Module Usage & Code Examples

### A. Prompt Analysis & Scoring
Analyze an incoming prompt to compute its quality metrics, check for weaknesses, and calculate its grade.

```python
from member1 import analyze_prompt, detect_weaknesses, calculate_prompt_score

# 1. Analyze the prompt metrics
prompt = "Explain machine learning in under 100 words. Format as a markdown table."
analysis = analyze_prompt(prompt)

# 2. Detect weaknesses (flagged if score is below the threshold of 0.40)
weaknesses = detect_weaknesses(analysis)

# 3. Compute overall weighted score and qualitative grade
score_report = calculate_prompt_score(analysis)

print("Analysis Output:", analysis)
print("Weaknesses detected:", weaknesses)
print("Score Report:", score_report)
```

### B. Response Evaluation
Compare the original response against the optimized response.

```python
from member1 import evaluate_response

original_response = "Machine learning is where computers learn from data. It includes supervised, unsupervised and reinforcement learning."
optimized_response = (
    "### Machine Learning Overview\n\n"
    "Machine learning (ML) is a subset of artificial intelligence focused on building "
    "systems that learn from, and make decisions based on, data.\n\n"
    "#### Key Types:\n"
    "1. **Supervised Learning**: Learned from labeled data.\n"
    "2. **Unsupervised Learning**: Discovers hidden patterns in unlabeled data."
)

eval_report = evaluate_response(original_response, optimized_response)
print("Evaluation Report:", eval_report)
```

## 6. Scoring Methodology

### A. Prompt Quality Score ($Q_p$)
The overall prompt quality is computed using a weighted linear combination of the 7 metric dimensions:
$$Q_p = \sum_{i=1}^{7} (w_i \times s_i)$$

Where:
* $s_i$ = Individual metric score (normalized to `[0.0, 1.0]`)
* $w_i$ = Metric weight

#### Default Research Weights:
* **Clarity** ($20\%$): Grammar, directness, and lack of ambiguous phrasing.
* **Specificity** ($20\%$): Topic boundary specification, depth, and target audience.
* **Context** ($15\%$): Role/persona declarations or background domain information.
* **Intent** ($15\%$): Detection of strong command verbs or explicit goals.
* **Constraints** ($10\%$): Restrictions, lengths, negative directives ("do not").
* **Output Format** ($10\%$): Formatting rules (JSON, markdown table, csv, lists).
* **Examples** ($10\%$): Few-shot demonstrations or input/output templates.

*Total weight sum = 1.0.* Weights are fully configurable and can be overridden by passing a custom dictionary to `calculate_prompt_score()`.

#### Grading Boundaries:
* $90 \le \text{Score} \le 100$ $\rightarrow$ **Excellent**
* $75 \le \text{Score} \le 89$ $\rightarrow$ **Good**
* $60 \le \text{Score} \le 74$ $\rightarrow$ **Fair**
* $40 \le \text{Score} \le 59$ $\rightarrow$ **Weak**
* $0 \le \text{Score} \le 39$ $\rightarrow$ **Poor**

---

### B. Response Improvement Score
Evaluates original and optimized responses across 6 axes:
* **Relevance** ($20\%$ weight)
* **Accuracy** ($20\%$ weight)
* **Completeness** ($20\%$ weight)
* **Coherence** ($15\%$ weight)
* **Helpfulness** ($15\%$ weight)
* **Semantic Similarity** ($10\%$ weight)

The improvement is calculated as:
$$\text{Improvement} = \text{Score(Optimized)} - \text{Score(Original)}$$

If $\text{Improvement} > 0.50$, the decision flags the `"optimized"` response as better. If it is below $-0.50$, the `"original"` is flagged. Otherwise, they are classified as `"similar"`.

## 7. Known Limitations & Future Improvements

### Heuristic Limitations
* The prompt metrics are computed using deterministic, rule-based text processing (regex pattern matching, vocabulary lookups, structural delimiters). While high-speed and local, these heuristics cannot capture the nuances of complex semantics.
* In local execution, response metrics like **Accuracy**, **Helpfulness**, and **Relevance** use structural baselines. It is fundamentally impossible to guarantee truth verification (Accuracy) or task alignment (Relevance) purely through offline regex rules without an external reference dataset or knowledge graph.

### Future Transition to LLM-as-a-Judge
The response evaluation module has been architected with **modular plugin scorers** (`score_coherence`, `score_completeness`, `score_helpfulness`, `score_relevance`, and `score_accuracy`). 

In the final integration phase:
- Member 3 should replace the internal heuristic algorithms in these functions with API calls to an LLM (e.g., Google Gemini 1.5/2.0 or OpenAI GPT-4o) operating as an evaluator.
- A sample prompt template for the LLM judge should look like:
  ```text
  You are an expert evaluator. Rate the following response on a scale from 0.0 to 1.0 for [Coherence/Completeness/Helpfulness/Accuracy] based on this original text.
  Original: {original_response}
  Evaluated Text: {optimized_response}
  Provide only the float score.
  ```

### Semantic Embedding Model
* For semantic similarity, we use `sentence-transformers/all-MiniLM-L6-v2`. This model is lightweight ($120\text{MB}$), runs locally on CPU, and loads lazily (loading only when `evaluate_response` is called) to prevent startup latency in prompt optimization loops.
